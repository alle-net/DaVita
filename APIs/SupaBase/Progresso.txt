Arquitetura original:

  Streamlit (Interface Web)
  Azure SQL Database (Free Tier)

==============================================================================
DECISÃO: MIGRAÇÃO PARA SUPABASE (03/07/2026)
==============================================================================

Após análise, optou-se por substituir Azure SQL + Azure Functions por Supabase.

Motivos:
  ✅ Supabase fornece PostgreSQL + REST API automática + Auth + RLS
  ✅ Elimina necessidade de codificar 7 endpoints manualmente
  ✅ Elimina necessidade de implementar JWT/hash de senha
  ✅ SDK Python nativo (supabase-py) — sem pyodbc problemático
  ✅ Deploy mais simples (apenas Streamlit → 1 serviço)

Arquitetura atual:
  Supabase Cloud (PostgreSQL + REST API automática + RLS)
    ├── Tabelas: fDados, dUsuarios, dRegional, dPendencias, dResponsavel
    ├── RLS (Row Level Security) protege os dados
    └── Autenticação: hash SHA-256 (login manual via Python)
  Streamlit (Interface Web)
    ├── Login (email + senha com hash)
    ├── Novo Registro (formulário com filtro ativo/inativo)
    ├── Consultar com filtros + exportar CSV
    └── Admin (gerenciar usuários)

==============================================================================
FLUXO DE NEGÓCIO (entendido na sessão)
==============================================================================

- Cada execução gera ~40 MIL linhas de pendências que os colaboradores devem
  justificar.
- O colaborador vê o nº da pendência no relatório Excel e informa (no
  Streamlit) o nº da pendência + justificativa + área responsável.
- O nº da pendência NÃO pode se repetir → constraint UNIQUE em fDados.IdPendencia.
- Excel + Power Query = relatório EXTERNO que consome as informações.

==============================================================================
DECISÕES TÉCNICAS DA SESSÃO
==============================================================================

1. Modelo: eliminar fDados com modelo estrela + dimensões. Novo modelo:
   1 fato (fDados) + 3 dimensões (dUsuarios, dJustificativas,
   dAreasResponsaveis).
2. fDados.Id → auto-incremento (SERIAL/BIGSERIAL), NÃO digitado.
3. dAreasResponsaveis: campo chamado "NomeAreaResponsavel" (corrigir typo
   "NomeJustificativa" do rascunho).
4. IdPendencia → campo inteiro livre, com UNIQUE (regra da gerência).
5. Autenticação → LOGIN MANUAL: hash SHA-256 na coluna SenhaUsuario,
   validação no Python. App usa a service_role key nos secrets do Streamlit
   (server-side, não exposta ao usuário).
6. Interface Streamlit → 2 telas: Login + Novo Registro.
7. Novo Registro inclui campo IdPendencia (aprovado incluir, já que existe a
   coluna).
8. Power Query conecta DIRETO ao PostgreSQL (porta 5432 + SSL, driver
   Npgsql/psqlODBC) — SEM REST API, SEM paginação. 40 mil linhas de uma vez.
9. Power Query é SOMENTE LEITURA — não grava no banco. Digitação é no
   Streamlit. Excel é o relatório de leitura.
10. Bulk INSERT no app: supabase-py aceita lista (lotes de ~500-1000);
    GET retorna até 1000/request (paginável com Range/offset) — mas Power
    Query não usa isso.
11. Link da API (se necessário): REST automático do Supabase
    (https://<projeto>.supabase.co/rest/v1/fDados?select=*) ou Accept: text/csv.
    O Streamlit gera o link do APP, não uma API.
