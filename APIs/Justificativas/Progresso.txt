RESUMO DO PLANO
================================================================================

- Sistema 100% online composto por API REST + Interface Web
- Hospedagem na Azure (Functions + App Service + SQL Database)
- Substituir planilha Excel por sistema web
- Cadastro e consulta de justificativas por regional
- ~50 registros/dia, até 30 usuários
- Custo zero estimado (tiers gratuitos)

Arquitetura:
  Azure Functions (API REST Python)
    ├── POST /auth          → Login JWT
    ├── GET /registros      → Listar com filtros
    ├── POST /registros     → Criar registro
    ├── GET /registros/{id} → Buscar específico
    ├── POST /usuarios      → Criar usuário (admin)
    ├── GET /usuarios       → Listar usuários (admin)
    └── DELETE /usuarios/{id} → Remover usuário (admin)
  Streamlit (Interface Web)
  Azure SQL Database (Free Tier)

Estrutura de pastas:
  projeto-api-justificativas/
    ├── api/            → Azure Functions
    ├── interface/      → Streamlit
    └── docs/           → Documentação

PROBLEMAS E RISCOS:
  1. Azure SQL Free Tier pode não existir mais em 2026
     → Alternativa: SQLite (Azure Storage) ou Azure Cosmos DB Free Tier
  2. Duas hospedagens (Functions + App Service) = complexidade extra
     → Sugestão: consolidar em Azure Functions + FastAPI + Jinja2
  3. pyodbc no Azure Functions é problemático (driver nativo)
     → Usar SQLAlchemy com configuração adequada
  4. Streamlit não tem autenticação/sessão robusta nativamente
     → Alternativa: FastAPI + Jinja2 + HTMX ou gerenciar st.session_state
  5. Plano F1 App Service: 60 min CPU/dia pode ser pouco
  6. Sem testes descritos no plano
  7. Dependência python-multipart listada mas não utilizada

PERGUNTAS EM ABERTO:

  - Regional é lista fixa? Vem de lookup table?
  - Cold start do Consumption Plan (até 10s) é aceitável?

RECOMENDAÇÕES:
